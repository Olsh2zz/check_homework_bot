# check_homework_bot

Telegram-бот для сдачи домашних работ. Студент присылает работу боту, преподаватель проверяет её вручную и ставит баллы. Студент получает ответ: ✅ работа принята или ❌ её нужно доработать, с комментарием.

Так выглядит ответ студенту после проверки:

```
✅ Работа «Лабораторная 3» принята
Баллы: 7.5/10
Комментарий: Аккуратная работа
```

```
❌ Работу «Лабораторная 4» нужно доработать
Баллы: 4/10
Комментарий: Нет вывода в конце отчёта

[🔁 Исправить] [❓ Уточнить]
```

## Что умеет

Команды через `/` набирать не нужно, всё делается кнопками. Единственная команда `/start` отправляется сама при первом открытии бота.

Кнопки студента:

- «📤 Сдать работу». Бот спрашивает название (например, «Лабораторная 3»), затем принимает текст, ссылки, фото и файлы. Сообщений может быть до 30. Кнопка «✅ Отправить» передаёт работу преподавателю.
- «📚 Мои работы». Список работ со статусами (⏳ на проверке, ✅ принято, ❌ на доработку), баллами и суммой баллов за принятые работы. Непроверенную работу здесь можно отозвать, отклонённую пересдать.
- «👤 Профиль». ФИО и группа, которые студент указал при регистрации, и кнопка «Изменить».
- «🔁 Исправить» под отклонённой работой. Студент присылает новую версию, преподаватель видит номер попытки и свой прошлый комментарий.
- «❓ Уточнить» под отклонённой работой. Студент пишет вопрос, ответ преподавателя приходит через бота.

Кнопки преподавателя:

- «✅ Принять» под работой. Бот просит баллы в формате `7/10` (балл и максимум преподаватель задаёт сам), затем комментарий или «Без комментария».
- «❌ На доработку». Бот просит комментарий, затем баллы или «Без баллов».
- «📥 Очередь проверки». Все непроверенные работы, начиная с самых давних. Нажатие на работу присылает её заново.

Раз в сутки бот напоминает преподавателю о работах, которые ждут проверки дольше двух дней. Час и число дней меняются в настройках.

Запустить бота можно двумя способами. На Vercel с базой в Supabase он работает постоянно и бесплатно, свой сервер не нужен. На своём компьютере он работает, пока открыт терминал: этого хватает, чтобы попробовать.

## Подготовка

1. Напишите в Telegram боту [@BotFather](https://t.me/BotFather) команду `/newbot` и получите токен.
2. Напишите боту [@userinfobot](https://t.me/userinfobot) с аккаунта преподавателя. Он покажет числовой ID.

Аккаунт преподавателя не может сдавать работы. Чтобы проверить бота в одиночку, нужен второй аккаунт Telegram в роли студента.

## Размещение на Vercel и Supabase

Vercel берёт код из ветки `main` репозитория на GitHub, поэтому код должен лежать в ней.

### 1. База в Supabase

1. Создайте проект на [supabase.com](https://supabase.com). Пароль базы, который вы зададите при создании, понадобится на следующем шаге.
2. Нажмите Connect вверху страницы проекта и скопируйте строку из блока Transaction pooler. Она выглядит так:

```
postgresql://postgres.abcdefgh:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
```

3. Замените `[YOUR-PASSWORD]` на пароль базы. Если в пароле есть символы вроде `@`, `/` или `#`, строка не разберётся: задайте пароль из букв и цифр.

Нужен именно Transaction pooler с портом 6543. Прямое подключение (порт 5432) рассчитано на программу, которая работает постоянно, а Vercel открывает новое соединение на каждое сообщение.

### 2. Два секрета

Выполните команду дважды и сохраните обе строки:

```bash
openssl rand -hex 32
```

Первая строка станет `WEBHOOK_SECRET`, вторая `CRON_SECRET`.

### 3. Проект в Vercel

1. На [vercel.com](https://vercel.com) создайте проект и выберите репозиторий `check_homework_bot`.
2. До первой сборки добавьте переменные окружения:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `TEACHER_ID` | числовой ID преподавателя |
| `DATABASE_URL` | строка подключения из шага 1 |
| `WEBHOOK_SECRET` | первый секрет |
| `CRON_SECRET` | второй секрет |

3. Запустите сборку. Проверить, что приложение отвечает, можно по адресу `https://<ваш-проект>.vercel.app/api/health`: в ответ придёт `{"ok":true}`.

Если Vercel предложит выбрать регион функций, выберите ближайший к региону базы в Supabase. Чем они дальше друг от друга, тем дольше бот отвечает.

### 4. Первичная настройка

Откройте в браузере адрес, подставив имя проекта и первый секрет:

```
https://<ваш-проект>.vercel.app/api/setup?secret=<WEBHOOK_SECRET>
```

Страница создаёт таблицы в базе и сообщает Telegram, куда присылать сообщения. Ответ при успехе:

```
{"ok":true,"webhook":"https://<ваш-проект>.vercel.app/api/webhook"}
```

Если в ответе `error`, в нём названа переменная, которую нужно исправить. После изменения переменных в Vercel проект надо пересобрать (Redeploy).

После этого напишите боту `/start` с аккаунта преподавателя, затем с аккаунта студента.

### Напоминания на Vercel

Время напоминания задано в файле `vercel.json` строкой `"schedule": "0 6 * * *"`. Это 6:00 по UTC, то есть 9:00 по Москве. Чтобы сдвинуть время, поменяйте час в этой строке и отправьте изменение в `main`. Переменная `REMINDER_HOUR` на Vercel не действует.

## Запуск на своём компьютере

Скопируйте файл `.env.example` в `.env` и впишите в него `BOT_TOKEN` и `TEACHER_ID`. Остальные переменные можно не трогать: данные будут лежать в файле `homework.db`.

Если этот же бот уже подключён к Vercel, локальный запуск остановится с сообщением о включённом вебхуке. Для проверки на компьютере создайте у @BotFather второго бота.

### macOS

Нужен Python 3.10 или новее. Проверить версию:

```bash
python3 --version
```

Если версия старше или команда не найдена, установите Python с сайта [python.org](https://www.python.org/downloads/macos/): Homebrew для этого не нужен.

Перейдите в папку проекта и создайте окружение:

```bash
python3 -m venv .venv
```

Установите библиотеки:

```bash
.venv/bin/pip install -r requirements.txt
```

Создайте файл настроек и заполните его в любом редакторе:

```bash
cp .env.example .env
```

Запустите бота:

```bash
.venv/bin/python -m bot
```

Бот работает, пока открыто окно терминала. Остановить: Ctrl+C.

### Windows

Установите Python 3.10 или новее с сайта [python.org](https://www.python.org/downloads/windows/) и отметьте в установщике пункт «Add python.exe to PATH». Откройте PowerShell в папке проекта.

```powershell
py -m venv .venv
```

```powershell
.venv\Scripts\pip install -r requirements.txt
```

```powershell
copy .env.example .env
```

Заполните `.env` в Блокноте и запустите:

```powershell
.venv\Scripts\python -m bot
```

### Docker

Для сервера есть `Dockerfile`. База хранится в томе `homework_data` и не пропадает при пересоздании контейнера.

```bash
docker build -t check-homework-bot .
```

```bash
docker run -d --name homework-bot --restart unless-stopped --env-file .env -v homework_data:/data check-homework-bot
```

## Тесты

Тестам не нужны токен и интернет: вместо Telegram подставляется заглушка, которая записывает все запросы бота.

```bash
.venv/bin/python -m unittest discover -s tests -t .
```

Всего 78 тестов:

- `test_scoring.py`: разбор оценки. `7/10`, `7,5/10` и `7 из 10` принимаются, `11/10`, `0/0`, `abc` и отрицательные числа отклоняются.
- `test_db.py`: запросы к базе. Черновик и отправка, оценка ставится один раз, цепочка пересдач, отзыв, порядок очереди, отбор работ для напоминания.
- `test_units.py`: проверка настроек, разбиение фото и файлов на альбомы по 10 штук, расчёт времени до напоминания.
- `test_scenarios.py`: диалоги целиком. Регистрация, сдача с текстом, фото и файлом, оценка, доработка и пересдача, отзыв во время проверки, вопрос и ответ, очередь. Отдельно проверяется, что студент не может нажать кнопки оценки и задать вопрос по чужой работе.
- `test_web.py`: запуск на Vercel. Запрос без секрета или с чужим секретом отклоняется, диалог продолжается между отдельными запросами, ошибка в обработчике не уходит в Telegram, напоминание по расписанию, первичная настройка.

По умолчанию тесты идут на SQLite в памяти. Чтобы прогнать их на Postgres, укажите адрес пустой тестовой базы. Тесты удаляют и заново создают в ней таблицы бота, поэтому рабочую базу сюда подставлять нельзя.

```bash
TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:5432/postgres .venv/bin/python -m unittest discover -s tests -t .
```

## Как это работает

У бота два способа получать сообщения. На своём компьютере он сам опрашивает серверы Telegram (long polling) и для этого должен работать постоянно. На Vercel постоянно работающей программы нет: Telegram присылает каждое сообщение запросом на адрес `/api/webhook`, Vercel запускает код на время этого запроса. Обработчики сообщений в обоих случаях одни и те же.

Из-за этого на Vercel нельзя ничего помнить между сообщениями. Шаг диалога (например, «ждём название работы») хранится в базе в таблице `dialogs`, а соединение с базой открывается на каждый запрос и закрывается после него.

Запросы к `/api/webhook` проверяются по секрету: Telegram возвращает его в заголовке, и запрос без него бот отклоняет. Иначе любой, кто узнал адрес, мог бы прислать поддельное сообщение от имени преподавателя.

База одна из двух: файл SQLite на своём компьютере или Postgres в Supabase. Запросы написаны один раз, различия движков собраны в `bot/drivers.py`. Таблиц пять: студенты, сдачи, содержимое сдач, вопросы и шаги диалогов. Файлы и фото бот не скачивает. Telegram выдаёт каждому вложению `file_id`, бот хранит его и по нему пересылает вложение преподавателю.

В Supabase для всех таблиц включена защита строк (row level security) без разрешающих правил. Так таблицы недоступны через публичный REST API Supabase, а бот подключается владельцем таблиц, на которого защита не действует.

У сдачи пять статусов: черновик, на проверке, принята, на доработке, отозвана. Пересдача создаёт новую запись, а не правит старую. Все попытки одной работы связаны полем `root_id` (id первой попытки) и пронумерованы в `attempt`. В списке студента видна только последняя попытка.

Оценка записывается запросом с условием «статус: на проверке». Если студент отозвал работу, пока преподаватель вводил баллы, запрос ничего не изменит, и преподаватель увидит сообщение, что работа отозвана.

Преподаватель определяется по `TEACHER_ID`. Его обработчики закрыты фильтром по этому ID, обработчики студентов закрыты обратным фильтром.

## Структура проекта

| Файл | Что в нём |
|---|---|
| `api/index.py` | точка входа для Vercel |
| `vercel.json` | расписание напоминаний на Vercel |
| `bot/web.py` | приём запросов на Vercel: вебхук, напоминание, первичная настройка |
| `bot/__main__.py` | запуск на своём компьютере |
| `bot/dispatcher.py` | подключение обработчиков, общее для обоих способов запуска |
| `bot/config.py` | чтение и проверка настроек |
| `bot/db.py` | схема базы и все запросы |
| `bot/drivers.py` | различия SQLite и Postgres |
| `bot/dialogs.py` | хранение шагов диалогов в базе |
| `bot/scoring.py` | разбор оценки «балл/максимум» |
| `bot/keyboards.py` | подписи кнопок и клавиатуры |
| `bot/texts.py` | тексты карточек, списков и результатов |
| `bot/delivery.py` | пересылка работы преподавателю, обновление карточки |
| `bot/reminders.py` | напоминание о непроверенных работах |
| `bot/states.py` | шаги диалогов |
| `bot/handlers/registration.py` | `/start`, ввод ФИО и группы |
| `bot/handlers/student.py` | действия студента |
| `bot/handlers/teacher.py` | действия преподавателя |
| `tests/` | тесты и заглушка Telegram |
| `.env.example` | образец настроек |
| `Dockerfile` | образ для своего сервера |
